# Imperial Campaign d20 Rules Contract

Status: implementation contract for the first vertical slice. This is an original rules profile using familiar d20 roleplaying math. The implementation does not import or reproduce a published game’s text or catalog.

## First playable slice

One player controls one original hero through a short, repeatable encounter in a compact 3D exploration space. The player selects clear actions from the game UI; the server resolves checks, attacks, damage, turns, and rewards. The AI Game Master may explain outcomes and offer context, but it cannot change a roll, character statistic, target statistic, reward, or encounter state.

## Character math

- Ability scores are integers from 1 to 30.
- Ability modifier: `floor((score - 10) / 2)`. Examples: 8 → -1, 10 → 0, 12 → +1, 18 → +4.
- Character level is 1–20.
- Proficiency bonus: +2 at levels 1–4; it increases by +1 every four levels, reaching +6 at level 17.
- A proficiency bonus is added once when the action is proficient. Expertise or other enhanced proficiency is not in the first slice.
- A check or saving throw total is: `d20 + relevant ability modifier + proficiency bonus if proficient + explicit situational bonus`.
- Success occurs when the total is greater than or equal to the server-selected DC.
- An attack total is: `d20 + attack ability modifier + proficiency bonus if proficient + explicit situational bonus`. It hits when the total is greater than or equal to the target's server-owned Armor Class, except that a natural 1 misses and a natural 20 hits and is critical.
- A natural 1 or 20 on a check or saving throw has no automatic result; only the total compared to the DC decides success.
- Advantage rolls two d20 and keeps the higher. Disadvantage rolls two and keeps the lower. If both apply, they cancel and only one die is rolled.
- The server records every die result, modifier, target number, result, and rules-version identifier in the action event.

## Combat slice

- Initiative is a Dexterity check, with ties broken deterministically by higher Dexterity score and then stable combatant ID.
- A combatant takes one turn in initiative order. The initial action set is move, attack, interact, use consumable, and end turn.
- Movement is limited by the character’s server-owned movement allowance and the map’s traversability data.
- One attack action resolves a single weapon attack. On a hit, damage is rolled from the server-owned weapon definition and applicable modifiers. A critical hit rolls the attack's damage dice twice; flat modifiers are applied once.
- Hit points cannot exceed maximum HP or fall below zero. At zero HP, the character is downed and cannot take normal actions until recovered or the encounter ends.
- The initial status set is poisoned, frightened, restrained, prone, and unconscious. Status effects have server-owned duration and action rules; the AI cannot invent effects.
- Encounter completion, XP, currency, and item grants are calculated by deterministic server code from the encounter definition and committed once.

## Encounter state and anti-replay rules

A campaign action request includes an authenticated player identity, encounter ID, expected state revision, action ID (UUID), and a typed action payload. The server:

1. Verifies the authenticated user owns or controls the active character in that encounter.
2. Loads the current encounter, character, map, equipment, and enemy values from trusted database rows.
3. Rejects an action if the encounter is complete, the player's turn is inactive, the state revision is stale, or the action ID has already been processed.
4. Validates range, line of sight, movement, inventory, resources, and action availability from authoritative state.
5. Generates random results on the server with a cryptographically secure random source.
6. Applies the result in a single database transaction, appends an immutable action event, and increments the state revision.
7. Returns the accepted event and updated state needed by the client.

The client never submits a die result, DC, armor class, damage total, enemy HP, item reward, or currency grant. Requests that fail validation do not consume a turn or mutate game state.

## Randomness and event record

Use Web Crypto `crypto.getRandomValues` in the Edge Function with rejection sampling for unbiased bounded integers. Do not use client randomness, timestamps, predictable seeds, or a random value generated by the language model.

Each event stores: event ID, encounter ID, revision before/after, actor ID, typed action, rules version, dice, modifiers, DC/AC where appropriate, outcome, state diff, and server timestamp. Event data must not contain secret service credentials or private AI prompts.

## First-slice content data

The first slice should use a small original set: one hero archetype, one weapon, one consumable, one map, and three enemy variants. Content values are data, not AI-generated at action time. Skill, race, weapon, potion, poison, and crafting catalogs can grow after this vertical slice is stable.

## Explicitly deferred

- Spell slots, spellcasting, multiclassing, feats, reactions, concentration, death saves, stealth contest edge cases, complex cover, and detailed tactical grid rules.
- NFTs, Solana transactions, marketplace listings, Imperial Games Network token integration, wagering, ranked PvP, and spectator broadcasts.
- AI-authored rule changes and AI roll generation.

## Implementation status

The server-only modules now include d20 checks and weapon damage in `rules.ts` and `combat.ts`, plus `encounter-actions.ts` for player move/attack/end-turn validation and a simple hostile turn that approaches the nearest hero along a deterministic grid path. Attacks and hostile turns share the same secure server roll and damage calculation. Interact/consumable actions, condition-driven advantage, persistence, transactional idempotency, an Edge Function endpoint, and client UI remain unimplemented. The code has not been compiled or tested. No database change or deployment has been made.

## Worked examples

- A hero with Dexterity 14 has modifier +2. At level 1, a proficient Dexterity check adds +2 proficiency. A d20 result of 13 with no situational bonus totals 17; against DC 15, the check succeeds.
- The same hero's unproficient check totals the d20 result plus +2, so that roll is 15 and succeeds against DC 15.
- On a check, a natural 20 with a total below the DC still fails, and a natural 1 can still succeed if the total reaches the DC.
- On an attack, a natural 1 always misses and a natural 20 always hits and triggers a critical damage roll.
- If advantage and disadvantage are both active, the event contains one d20 result. With advantage alone, it contains two results and selects the higher; with disadvantage alone, it contains two and selects the lower.
